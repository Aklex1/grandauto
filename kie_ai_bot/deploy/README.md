# Развёртывание kie_ai_bot на сервере Sage Valentina (89.169.38.152)

Ubuntu 24.04 LTS. Всё ставится в `/opt/kie_ai_bot`, четыре сервиса под systemd.

## Быстрый старт (3 команды на сервере)

```bash
ssh root@89.169.38.152

git clone -b claude/deploy-bot-sage-valentina-cd3p0q https://github.com/Aklex1/grandauto /opt/src
cd /opt/src/kie_ai_bot
bash deploy/install.sh
```

Первый запуск создаст `/opt/kie_ai_bot/.env` из шаблона и остановится с предупреждением.
Заполните `.env` (значения — из вашего бэкапа, см. раздел «Переменные») и выполните:

```bash
bash /opt/src/kie_ai_bot/deploy/start.sh
```

## Что поднимается

| Сервис               | Порт  | Назначение                                                        |
|----------------------|-------|-------------------------------------------------------------------|
| `kie-bot`            | 8010  | Сам бот (aiogram polling) + FastAPI, куда KIE шлёт результаты      |
| `kie-webhook`        | 8000  | YooMoney-вебхук пополнений **в Telegram-боте**                     |
| `kie-app-webhook`    | 8002  | YooMoney-вебхук пополнений **в мобильном приложении**              |
| `app-api`            | 8011  | API мобильного приложения (NeuroHub App API)                       |
| (метрики kie-webhook)| 8003  | Prometheus, опционально (`WEBHOOK_METRICS_PORT=0` — выключить)     |

Дополнительно ставится и включается локальный **Redis** (FSM-состояния и rate limiting).

## Управление

```bash
bash deploy/status.sh      # сервисы, порты, MySQL, Telegram API, внешний IP
bash deploy/logs.sh        # логи всех четырёх сервисов сразу
bash deploy/start.sh       # перезапуск после правки .env
systemctl restart kie-bot  # перезапуск одного сервиса
journalctl -u kie-bot -f   # логи одного сервиса
```

Обновить код на сервере: `git -C /opt/src pull && bash /opt/src/kie_ai_bot/deploy/install.sh`
(`.env`, `venv` и загрузки при этом не трогаются).

## Переменные `.env`

Шаблон — `deploy/env.example`. Значения `ЗАПОЛНИТЬ` берутся из `.env` вашего бэкапа
(токен бота, `KIE_API_KEY`, кошельки YooMoney, доступы к MySQL, SMTP, `WORDPRESS_API_KEY`).
`JWT_SECRET` установщик генерирует сам.

Формат строгий: `KEY=value`, без кавычек, без пробелов вокруг `=`, без комментариев в конце строки.

Два новых параметра, которых не было в бэкапе (раньше адрес был зашит в коде):

```
CALLBACK_BASE_URL=http://89.169.38.152:8010
APP_API_BASE_URL=http://89.169.38.152:8011
```

Это публичные адреса **этого** сервера. Раньше в коде было зашито `http://techscore.ru:8010`
(старый сервер `212.74.231.21`) — 26 мест в `main.py`. Теперь адрес берётся из `.env`.

## Обязательные действия вне сервера

Без них бот запустится, но работать будет не полностью:

1. **MySQL хостинга (beget).** База внешняя: `akklexb6.beget.tech`. Beget пускает
   удалённые подключения только с разрешённых IP — в панели Beget добавьте
   `89.169.38.152` в список разрешённых. Проверка: `bash deploy/status.sh`
   (строка «MySQL доступен»).

2. **YooMoney → HTTP-уведомления.** В настройках кошелька (yoomoney.ru → Настройки →
   HTTP-уведомления) укажите новый адрес:
   - кошелёк бота: `http://89.169.38.152:8000/yoomoney-webhook`
   - кошелёк приложения: `http://89.169.38.152:8002/yoomoney-webhook`

   Без этого **платежи не будут зачисляться**: деньги придут на кошелёк, но баланс в боте
   не пополнится. Если нужен HTTPS — направьте на сервер поддомен и поставьте nginx +
   certbot, тогда адреса будут вида `https://ваш-домен/yoomoney-webhook`.

3. **Один активный бот на токен.** Telegram отдаёт апдейты только одному polling-клиенту.
   Убедитесь, что бот остановлен на старом сервере (`212.74.231.21`), иначе апдейты
   будут делиться между двумя копиями.

4. **Порты наружу.** 8000, 8002, 8010, 8011 должны быть доступны из интернета
   (KIE шлёт callback-и на 8010, YooMoney — на 8000/8002). Установщик открывает их в ufw,
   если ufw активен; проверьте также фаервол хостинга.

## Проверка после запуска

```bash
bash deploy/status.sh                     # всё зелёное
curl -s localhost:8011/docs -o /dev/null -w '%{http_code}\n'   # 200 — app-api жив
curl -s -X POST localhost:8000/yoomoney-webhook -d 'x=1'       # 400 Invalid data — вебхук жив
```

В Telegram: `/start` боту → меню; пополнение на минимальную сумму → баланс должен вырасти
после оплаты (в логах `journalctl -u kie-webhook -f` появится «Баланс пользователя ... пополнен»).

## Известные особенности бэкапа

- В `main.py` после блока `if __name__ == "__main__":` остался «мёртвый» код —
  обработчики кнопки «Голос в текст» (`speech_to_text_start`). Они никогда не
  регистрируются, потому что находятся ниже точки входа, и ссылаются на
  несуществующий класс `SpeechToTextStates`. Это было и в бэкапе; на работу
  остальных функций не влияет. Если нужна расшифровка речи — надо чинить отдельно.
- В `webhook_server.py` сервер метрик занимал порт 8002, тот же, что и вебхук приложения.
  Перенесён на 8003 (`WEBHOOK_METRICS_PORT`).
- Файлы-дубли из бэкапа (`main_02_09_25.py`, `webhook_server copy.py`, `bot.db`,
  `app_uploads/*`) в развёртывание не включены.
