# Автопостинг: каналы-источники → Kie AI → целевой канал

Модуль `autopost.py`. Работает внутри сервиса `kie-bot`, отдельный сервис не нужен.

## Что делает

1. Обходит каналы-источники и берёт свежие посты с фотографией.
2. Промпт берёт из комментариев к посту. **Комментария нет — пост пропускается**,
   обход идёт к более раннему.
3. Отправляет в Kie AI (`google/nano-banana-edit`) промпт и **только референсное
   фото** с сервера (`/opt/refer/refer.jpg`). Картинка исходного поста не
   скачивается и не используется — генерация идёт поверх вашей модели.
4. Результат публикует в целевой канал вместе с промптом: промпт идёт в подписи,
   если помещается в лимит Telegram, иначе комментарием под постом. На два поста
   публикация не разбивается никогда.

С каждого канала берётся не больше `AUTOPOST_PER_CHANNEL_DAILY` новых постов
в сутки (по умолчанию 2). Суточный потолок — это число, умноженное на количество
каналов; публикации растягиваются равномерно по суткам, а не выкладываются пачкой.
Для 10 каналов по 2 поста получается 20 публикаций в сутки, то есть примерно
одна каждые 72 минуты.

Уже обработанные посты повторно не берутся: пара «канал + id поста» уникальна
в базе, а список известных постов канала проверяется перед каждым обходом.
База переживает перезапуск сервиса, так что после рестарта ничего не дублируется.

Состояние хранится в отдельном SQLite `/opt/kie_ai_bot/autopost.db`, основную
MySQL-базу модуль не трогает. Баланс пользователей не списывается: генерации
идут за счёт владельца.

## Пробный прогон

Администратор может проверить всю цепочку прямо из бота:

```
/autopost_test        — по одному посту с каждого канала
/autopost_test 2      — по два поста с каждого канала
```

Команда берёт свежие посты, генерирует и публикует их сразу, минуя суточный
лимит и равномерное распределение, а затем присылает отчёт по каждому каналу:
опубликовано, пропущено (нет промпта в комментариях) или ошибка с причиной.
Прогон на 10 каналов занимает несколько минут.

## Формат публикации

Пост собирается так же, как оформлены остальные посты канала:

```
#Женский
БОТ через который можно сделать фото.      <- ссылка AUTOPOST_BOT_URL
САЙТ через который можно сделать фото.     <- ссылка AUTOPOST_SITE_URL
Канал с промтами в MAX 📱                  <- ссылка AUTOPOST_MAX_URL
⚜️⚜️⚜️⚜️⚜️⚜️⚜️⚜️
```

Промпт печатается цитатой моноширинным шрифтом, чтобы читатель мог скопировать
его одним касанием. Короткий промпт помещается прямо в подпись под картинкой;
длинный (а они обычно за тысячу символов) уходит комментарием под постом.
Ссылка на бота есть в каждом посте. Хештеги берутся из подписи исходного поста;
если их там нет — подставляется `AUTOPOST_HASHTAGS`.

Комментарий отправляется в группу обсуждений целевого канала, её id определяется
автоматически при старте (или задаётся в `AUTOPOST_DISCUSSION_CHAT_ID`).
Чтобы ответить в группу, нужен id поста уже внутри неё — Bot API такого
соответствия не отдаёт, поэтому его подсказывает Telethon. Если Telethon
недоступен, модуль ждёт автопересылку до `AUTOPOST_DISCUSSION_WAIT` секунд,
а в самом крайнем случае дописывает промпт в подпись, обрезав до лимита —
пост без промпта не остаётся.

Настраивается всё через `.env`:

```
AUTOPOST_BOT_URL=https://t.me/Neuro_HubAI_bot?start=Sv_lana0707
AUTOPOST_SITE_URL=https://genius-bot.ru/neurohub/?ref=sv07
AUTOPOST_MAX_URL=https://max.ru/join/...
AUTOPOST_HASHTAGS=#Женский
AUTOPOST_FOOTER=⚜️⚜️⚜️⚜️⚜️⚜️⚜️⚜️
```

## Обязательные условия

1. **Бот — администратор в канале-источнике.** Иначе Telegram просто не отдаёт боту посты
   этого канала. Проверка:
   `curl -s "https://api.telegram.org/bot<TOKEN>/getChat?chat_id=-1002740687728"` —
   должно вернуться `"ok":true`, а не `chat not found`.

2. **Бот — администратор в группе обсуждений источника.** Комментарии живут именно там.
   Обычному участнику-боту Telegram отдаёт не все сообщения (privacy mode), админу — все.

3. **Доступ Kie AI к картинкам.** По умолчанию (`AUTOPOST_UPLOAD_VIA_KIE=1`) исходные
   картинки загружаются в файловое хранилище самого Kie AI, поэтому публичный адрес боту
   не нужен. Результат приходит на `/autopost-callback`, а если этот адрес снаружи
   недоступен — забирается опросом `recordInfo` через `AUTOPOST_POLL_AFTER_MINUTES` минут.
   То есть автопостинг работает даже при закрытом порте 8010, просто с задержкой в
   несколько минут. Если открыть порт наружу и поставить `AUTOPOST_UPLOAD_VIA_KIE=0`,
   картинки будут отдаваться с собственного FastAPI, а результат приходить сразу.

## Статусы постов в базе

| Статус       | Значение                                          |
|--------------|---------------------------------------------------|
| `ready`      | промпт есть, ждём своей очереди по расписанию      |
| `generating` | задача ушла в Kie AI, ждём результат               |
| `published`  | опубликовано в целевом канале                      |
| `error`      | ошибка, текст в колонке `error`                    |

Посмотреть очередь:

```bash
sqlite3 /opt/kie_ai_bot/autopost.db \
  "SELECT id, source_chat_id, source_msg_id, status, substr(prompt,1,40), error \
   FROM autopost_posts ORDER BY id DESC LIMIT 20;"
```

Повторить пост вручную (вернуть в очередь):

```bash
sqlite3 /opt/kie_ai_bot/autopost.db \
  "UPDATE autopost_posts SET status='ready', task_id=NULL, sent_at=NULL WHERE id=123;"
```

## Режим Telethon: чужой канал-источник

Bot API не отдаёт боту содержимое каналов, где он не администратор. Если канал-источник
чужой, посты и комментарии читает модуль `telethon_source.py` от имени обычного аккаунта.
Найденные посты попадают в ту же очередь, дальше работает общий конвейер: суточный лимит,
генерация в Kie AI, публикация в фирменном оформлении.

### Настройка

1. Получите `api_id` и `api_hash` на https://my.telegram.org → API development tools.
2. Впишите в `/opt/kie_ai_bot/.env`:

```
AUTOPOST_ENABLED=1
TELETHON_ENABLED=1
TELETHON_API_ID=1234567
TELETHON_API_HASH=ваш_хеш
TELETHON_SESSION=/opt/kie_ai_bot/telethon.session
```

3. Аккаунт, под которым будете входить, должен быть подписан на канал-источник.
4. Один раз выполните интерактивный вход (номер телефона, код из Telegram,
   при необходимости облачный пароль):

```bash
cd /opt/kie_ai_bot
venv/bin/python deploy/telethon_login.py
```

   Скрипт создаст файл сессии и сразу проверит, виден ли канал-источник.

5. `systemctl restart kie-bot` — дальше вход больше не потребуется.

### Как выбирается промпт

Под постом просматриваются комментарии (до `TELETHON_COMMENTS_LIMIT`). Берётся самый
длинный комментарий длиной не меньше `TELETHON_MIN_PROMPT_LEN` символов — короткие
реплики вроде «огонь» отсекаются. Если комментариев нет совсем, берётся текст самого поста.

**Если под постом промпта нет, обход не останавливается** — модуль спускается к более
раннему посту и так далее, пока не наберёт нужное число постов с промптом или не
просмотрит `TELETHON_MAX_LOOKBACK` постов (по умолчанию 60). Посты без промпта остаются
в очереди со статусом `waiting_prompt` и перепроверяются на каждом проходе: комментарий
мог появиться позже. Фото скачивается только когда промпт найден — лишнего трафика нет.

Сколько постов нужно найти за проход, считается от суточного лимита: сколько ещё осталось
свободных слотов на сегодня, за вычетом того, что уже лежит в очереди готовым. При самом
первом запуске берётся не больше `TELETHON_BACKFILL_LIMIT` постов (по умолчанию 3).
Канал опрашивается раз в `TELETHON_POLL_INTERVAL` секунд.

### Ограничения

Файл сессии равнозначен доступу к аккаунту — держите его с правами 600 и не копируйте
наружу. Частые запросы к чужому каналу Telegram может ограничивать (FloodWait), поэтому
интервал опроса по умолчанию 10 минут: для 2–3 постов в сутки этого с запасом хватает.
