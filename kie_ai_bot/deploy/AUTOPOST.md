# Автопостинг: канал-источник → Kie AI → целевой канал

Модуль `autopost.py`. Работает внутри сервиса `kie-bot`, отдельный сервис не нужен.

## Что делает

1. Ловит новый пост с фотографией в канале-источнике.
2. Ждёт промпт в комментариях к этому посту (связанная группа обсуждений).
3. Скачивает фото поста, добавляет референсное фото девушки (`/opt/refer/refer.jpg`)
   и отправляет обе картинки с промптом в Kie AI (`google/nano-banana-edit`).
4. Готовое изображение публикует в целевой канал, подпись — текст промпта.

Не больше `AUTOPOST_DAILY_LIMIT` постов в сутки (по умолчанию 3). Всё, что сверх лимита,
лежит в очереди и уходит на следующий день — очередь разгребает фоновый воркер.

Состояние хранится в отдельном SQLite `/opt/kie_ai_bot/autopost.db`, основную MySQL-базу
модуль не трогает. Баланс пользователей не списывается: генерации идут за счёт владельца.

## Включение

В `/opt/kie_ai_bot/.env`:

```
AUTOPOST_ENABLED=1
AUTOPOST_SOURCE_CHAT_ID=-1002740687728
AUTOPOST_TARGET_CHAT_ID=-1003337013037
AUTOPOST_REFERENCE_IMAGE=/opt/refer/refer.jpg
AUTOPOST_DAILY_LIMIT=3
```

Положите референсное фото:

```bash
mkdir -p /opt/refer
# скопируйте свой файл в /opt/refer/refer.jpg
systemctl restart kie-bot
journalctl -u kie-bot -f | grep autopost
```

## Формат публикации

Пост собирается ровно так же, как оформлены остальные посты канала:

```
#Женский
БОТ через который можно сделать фото.      <- ссылка AUTOPOST_BOT_URL
САЙТ через который можно сделать фото.     <- ссылка AUTOPOST_SITE_URL
Канал с промтами в MAX 📱                  <- ссылка AUTOPOST_MAX_URL
> промпт (цитата моноширинным шрифтом, копируется по тапу)
⚜️⚜️⚜️⚜️⚜️⚜️⚜️⚜️
```

Ссылка на бота ставится всегда. Хештеги берутся из подписи исходного поста;
если их там нет — подставляется `AUTOPOST_HASHTAGS`. Настраивается всё через `.env`:

```
AUTOPOST_BOT_URL=https://t.me/Neuro_HubAI_bot?start=Sv_lana0707
AUTOPOST_SITE_URL=https://genius-bot.ru/neurohub/?ref=sv07
AUTOPOST_MAX_URL=https://max.ru/join/...
AUTOPOST_HASHTAGS=#Женский
AUTOPOST_FOOTER=⚜️⚜️⚜️⚜️⚜️⚜️⚜️⚜️
```

Лимит подписи к фото в Telegram — 1024 видимых символа. Если промпт длинный и не влезает,
фото уходит с шапкой, а промпт — отдельным сообщением-ответом к нему.

## Обязательные условия

1. **Бот — администратор в канале-источнике.** Иначе Telegram просто не отдаёт боту посты
   этого канала. Проверка:
   `curl -s "https://api.telegram.org/bot<TOKEN>/getChat?chat_id=-1002740687728"` —
   должно вернуться `"ok":true`, а не `chat not found`.

2. **Бот — администратор в группе обсуждений источника.** Комментарии живут именно там.
   Обычному участнику-боту Telegram отдаёт не все сообщения (privacy mode), админу — все.

3. **`CALLBACK_BASE_URL` доступен из интернета.** По нему Kie AI забирает исходные картинки
   (`/autopost/media/...`, `/autopost/reference.jpg`) и присылает результат
   (`/autopost-callback`). Если порт 8010 закрыт снаружи — генерации не будет.

## Статусы постов в базе

| Статус           | Значение                                              |
|------------------|-------------------------------------------------------|
| `waiting_prompt` | пост поймали, ждём промпт в комментариях               |
| `ready`          | промпт есть, ждём свободный слот суточного лимита      |
| `generating`     | задача ушла в Kie AI, ждём callback                    |
| `published`      | опубликовано в целевом канале                          |
| `error`          | ошибка, текст в колонке `error`                        |
| `expired`        | промпт не появился за `AUTOPOST_PROMPT_WAIT_HOURS`     |

Посмотреть очередь:

```bash
sqlite3 /opt/kie_ai_bot/autopost.db \
  "SELECT source_msg_id, status, substr(prompt,1,40), error FROM autopost_posts ORDER BY source_msg_id DESC LIMIT 20;"
```

Повторить пост вручную (вернуть в очередь):

```bash
sqlite3 /opt/kie_ai_bot/autopost.db \
  "UPDATE autopost_posts SET status='ready', task_id=NULL, sent_at=NULL WHERE source_msg_id=123;"
```

## Режим Telethon: чужой канал-источник

Bot API не отдаёт боту содержимое каналов, где он не администратор. Если канал-источник
чужой, посты и комментарии читает модуль `telethon_source.py` от имени обычного аккаунта.
Найденные посты попадают в ту же очередь, дальше работает общий конвейер: суточный лимит,
генерация в Kie AI, публикация в фирменном оформлении.

### Настройка

1. Получите `api_id` и `api_hash` на https://my.telegram.org → API development tools.
2. Впишите в `/opt/kie_ai_bot/.env`:

```
AUTOPOST_ENABLED=1
TELETHON_ENABLED=1
TELETHON_API_ID=1234567
TELETHON_API_HASH=ваш_хеш
TELETHON_SESSION=/opt/kie_ai_bot/telethon.session
```

3. Аккаунт, под которым будете входить, должен быть подписан на канал-источник.
4. Один раз выполните интерактивный вход (номер телефона, код из Telegram,
   при необходимости облачный пароль):

```bash
cd /opt/kie_ai_bot
venv/bin/python deploy/telethon_login.py
```

   Скрипт создаст файл сессии и сразу проверит, виден ли канал-источник.

5. `systemctl restart kie-bot` — дальше вход больше не потребуется.

### Как выбирается промпт

Под постом просматриваются комментарии (до `TELETHON_COMMENTS_LIMIT`). Берётся самый
длинный комментарий длиной не меньше `TELETHON_MIN_PROMPT_LEN` символов — короткие
реплики вроде «огонь» отсекаются. Если комментариев нет совсем, берётся текст самого поста.

При первом запуске забираются последние `TELETHON_BACKFILL_LIMIT` постов (по умолчанию 3),
дальше — только новые. Канал опрашивается раз в `TELETHON_POLL_INTERVAL` секунд.

### Ограничения

Файл сессии равнозначен доступу к аккаунту — держите его с правами 600 и не копируйте
наружу. Частые запросы к чужому каналу Telegram может ограничивать (FloodWait), поэтому
интервал опроса по умолчанию 10 минут: для 2–3 постов в сутки этого с запасом хватает.
