# Пересыльщик сообщений в Telegram

## Зачем

Сайт живёт на Beget, и оттуда `api.telegram.org` недоступен: соединение
обрывается за три миллисекунды — это закрытый доступ, а не медленная
сеть. Из-за этого заявки с сайта копятся в журнале админки
(«Заявки с лендинга»), но уведомления не приходят.

На вашем сервере телеграм доступен — там же работает бот. Эта служба
принимает от сайта текст и отдаёт его боту.

Токен бота остаётся на сервере: сайт его не знает и не передаёт. Сайт
знает только адрес службы и общий ключ.

## Что нужно решить до установки

1. **Каким ботом слать уведомления.** Его токен попадёт в настройки
   службы. Подойдёт тот же бот, что уже работает на сервере.
2. **Кому слать.** Ваш `chat_id` — тот же, что сейчас указан в настройках
   плагина на сайте.
3. **Свободен ли порт.** На сервере уже заняты 8000, 8010 и 8090.
   Проверьте: `ss -ltnp | grep 8020`.

## Установка

```bash
sudo mkdir -p /opt/telegram-relay
sudo cp relay.py /opt/telegram-relay/
sudo cp telegram-relay.service /etc/systemd/system/

# Ключ для сайта — длинная случайная строка. Запомните её: тот же
# ключ понадобится вписать в настройки плагина.
RELAY_KEY=$(head -c 32 /dev/urandom | base64 | tr -d '/+=' | head -c 40)
echo "$RELAY_KEY"

sudo tee /etc/telegram-relay.env >/dev/null <<ENV
TELEGRAM_BOT_TOKEN=сюда_токен_бота
TELEGRAM_CHAT_ID=сюда_chat_id
RELAY_TOKEN=$RELAY_KEY
ENV
sudo chmod 600 /etc/telegram-relay.env

sudo systemctl daemon-reload
sudo systemctl enable --now telegram-relay
systemctl status telegram-relay --no-pager
```

Проверка, что служба жива:

```bash
curl -s http://127.0.0.1:8020/health
# {"ok": true, "service": "telegram-relay"}
```

Проверка отправки (сообщение придёт вам в телеграм):

```bash
curl -s -X POST http://127.0.0.1:8020/send \
  -H "X-Relay-Token: $RELAY_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"Проверка пересыльщика"}'
```

## Доступ снаружи

Сайту нужно достучаться до службы. Открывать порт 8020 всему интернету
не обязательно: служба и так требует ключ, но лишняя дверь ни к чему.

Если на сервере стоит nginx, аккуратнее отдать её через него по адресу
вида `https://ваш-домен/telegram-relay/send`:

```nginx
location /telegram-relay/ {
    proxy_pass http://127.0.0.1:8020/;
    proxy_set_header X-Relay-Token $http_x_relay_token;
}
```

Без nginx достаточно разрешить порт в брандмауэре:

```bash
sudo ufw allow 8020/tcp
```

## Что вписать на сайте

Админка → Genius Sounds → «Заявки с лендинга»:

* **Адрес пересыльщика** — `https://ваш-домен/telegram-relay/send`
  или `http://89.169.38.152:8020/send`;
* **Ключ пересыльщика** — та самая длинная строка из `RELAY_KEY`.

Сайт сначала пробует отправить напрямую (вдруг хостинг откроет доступ),
и только при отказе идёт через пересыльщик. В журнале заявок видно, каким
путём ушло сообщение.

## Если что-то не так

```bash
journalctl -u telegram-relay -n 50 --no-pager
```

* `неверный ключ` — ключ на сайте и в `/etc/telegram-relay.env` разные;
* `этот получатель не разрешён` — сайт прислал чужой `chat_id`;
  разрешённые перечисляются в `TELEGRAM_ALLOWED_CHATS` через запятую;
* `слишком часто` — больше тридцати сообщений в минуту; предел задан
  в самом `relay.py`.
