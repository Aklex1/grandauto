# Genius Sounds

Плагин-компаньон к `kie-tts-wp` для сайта genius-bot.ru. Делает три вещи:

1. **Переверстывает каталог звуков** — перехватывает шорткод `[kie_tts_sounds_catalog]`
   и рисует адаптивные страницы вместо старого плоского списка.
2. **Импортирует звуки** — серверный парсер наполняет категории реальными MP3.
3. **Студия звуков и SFX** — вторая версия панели генерации, но под звуки и спецэффекты
   на Suno (KIE), а не под озвучку текста.

Базовый плагин `kie-tts-wp` не изменяется: Genius Sounds ставится рядом и при
деактивации возвращает всё как было.

## Почему компаньон, а не правка kie-tts-wp

Переустановка `kie-tts-wp` через ZIP стирает содержимое папки плагина, а редактор
плагинов в админке умеет менять только существующие файлы и не умеет создавать новые.
Отдельный плагин снимает оба ограничения и не рискует уронить рабочую озвучку.

## Каталог

- `[kie_tts_sounds_catalog]` — тот же шорткод, новый рендер. Старые ссылки
  (`/sounds-catalog/`, `/sounds-catalog/<slug>/`, `?sound_cat=<slug>`) работают
  без изменений: используются правила ЧПУ и query var `kie_sound_category`
  базового плагина.
- Главная: поиск по каталогу (`?gs_q=`), пагинация (`?gs_page=`), категории со
  звуками показываются первыми.
- Страница категории: хлебные крошки, сетка карточек с общим плеером,
  скачивание, пагинация по 24 звука, перелинковка, SEO-тексты сохранены.
- CTA «создайте звук сами» — на главной каталога и на каждой странице категории,
  ведёт в студию с подставленным описанием.
- Шапка и подвал темы перекрашены под тёмные страницы (`assets/css/chrome.css`).
  Базовый плагин на своих страницах их прячет — из-за чего посадочные страницы
  каталога оставались без навигации; мы их возвращаем и заодно восстанавливаем
  отступ под фиксированной шапкой.

## SEO страниц категорий

Все 945 категорий живут на одной WP-странице, поэтому и тема, и базовый плагин
выдавали им один и тот же `<title>`, одинаковое описание и `canonical` на
`/sounds-catalog/` — то есть помечали каждую категорию дублем индекса каталога.

`GS_Seo` чинит это: свой заголовок и описание у каждой категории, `canonical`
на саму себя, а несуществующий слаг отдаёт 404 вместо мягкого 200. Заголовок
правится фильтром `document_title_parts`, остальные теги — переписыванием
буфера `wp_head`: их печатают сразу несколько источников без общих фильтров.

### Данные

`wp-content/uploads/genius-sounds/`

```
catalog.json                 категории, тексты и списки звуков
files/<slug>/<id>-<name>.mp3 сами звуки
generated/<taskId>.mp3       локальные копии сгенерированных звуков
```

Хранилище лежит в `uploads`, а не в папке плагина: обновление плагина не сносит библиотеку.

При первом запуске `catalog.json` наполняется из
`kie-tts-wp/assets/sounds/catalog.json` — оттуда берутся только SEO-тексты 945 категорий.
Списки звуков из старого файла отбрасываются: там во всех категориях лежали одни и те же
25 записей с несуществующими путями (кириллица схлопнулась в дефисы, файлы отдавали 404).

## Импорт звуков

Админка: **Звуки** → блок «Импорт звуков».

- Очередь слагов хранится в опции, обрабатывается пачками по 20 секунд —
  так импорт не упирается в `max_execution_time`.
- Двигается либо кроном (`gs_import_tick`), либо кнопкой «Обработать пачку».
- Файлы качает сам сервер, содержимое проверяется по content-type и размеру,
  между запросами пауза 200 мс. Предел размера файла настраивается
  (`gs_import_max_file_mb`, по умолчанию 8 МБ): длинные музыкальные треки
  занимают в разы больше коротких эффектов и быстро съедают диск.
- Крупные разделы источника (`muz`, `avto`, `predmetyi`) — витрины подкатегорий
  без собственных треков; для них подборка собирается из дочерних категорий.
- Занятое и свободное место видно на экране «Звуки».
- Повторный импорт уже заполненной категории пропускается, если не включён режим
  перезаписи; ранее скачанные файлы не качаются заново.

REST (только для `manage_options`):

```
POST genius-sounds/v1/import/start   {slugs?, count?, limit?, force?}
POST genius-sounds/v1/import/tick
POST genius-sounds/v1/import/stop
GET  genius-sounds/v1/import/status
```

## Студия звуков

Страница `/sound-generator/` (шорткод `[genius_sfx_studio]`).

- Описание звука, 14 пресетов, три типа: отдельный эффект / атмосфера / бесшовный луп.
- Модель Suno `V5` (эффекты) или `V5_5` (атмосфера, музыкальные подложки),
  длительность-ориентир, темп, тональность, зацикливание.
- Промпт достраивается под SFX: к описанию добавляются `realistic cinematic sound effect`,
  `sharp transient, clean tail`, `no music, no voices, no melody` и длительность —
  без этого Suno норовит выдать музыку вместо эффекта.
- Списание с того же баланса, что и озвучка (`wp_kie_tts_balance`), цена настраивается
  в админке. При провале генерации деньги возвращаются.
- Гость с описанием звука после входа возвращается в студию, а не на
  `/tts-dashboard/`: адрес возврата запоминается в куке `gs_return_to` при
  переходе на страницу входа (базовый плагин при любом способе входа ведёт
  на дашборд озвучки).
- В интерфейсе и текстах ошибок провайдер генерации не называется.
- История генераций пишется в `wp_kie_tts_generations` с `voice = sfx:<модель>`,
  так что попадает в общую статистику пользователя.
- Готовый звук копируется к себе в `generated/` — ссылки KIE живут недолго.

Страница `/ai-zvuki/` (`[genius_sfx_showcase]`) — витрина примеров.

### Внешний API (только для разработки)

```
POST https://api.kie.ai/api/v1/generate/sounds        prompt, model, soundLoop, soundTempo, soundKey, callBackUrl
GET  https://api.kie.ai/api/v1/generate/record-info   ?taskId=...
```

Ключ берётся из опции `kie_tts_api_key` базового плагина — отдельно настраивать
не нужно. На сайте провайдер нигде не упоминается: в интерфейсе модели названы
«Стандартная» и «Расширенная», ошибки говорят про «сервис генерации».

REST студии (нужен вход):

```
POST genius-sounds/v1/sfx/generate   {prompt, mode, model, seconds, loop, tempo?, key?}
GET  genius-sounds/v1/sfx/status/<taskId>
GET  genius-sounds/v1/sfx/history
GET  genius-sounds/v1/sfx/balance
POST genius-sounds/v1/sfx/callback   (публичный, для колбэков KIE)
```

## Правовая заметка по импорту

Импортёр скачивает файлы со стороннего каталога звуков. Права на эти записи
принадлежат их авторам и источнику, и условия источника не дают автоматически права
на повторную публикацию библиотеки на другом домене. Перед массовым импортом стоит
проверить условия использования источника; сгенерированные в студии звуки такого
ограничения не имеют.
