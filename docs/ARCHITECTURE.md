# Архитектура контент-завода

## Общая схема

```
                    ┌────────────────────────────────────────────┐
   браузер ────────▶│ FastAPI (app/main.py)                      │
   (пароль)         │  сессия-cookie, серверный рендер Jinja2    │
                    └───────┬───────────────────────┬────────────┘
                            │                       │
                    ┌───────▼────────┐      ┌───────▼─────────────┐
                    │ БД (SQLAlchemy)│      │ Хранилище на диске  │
                    │ SQLite / PG    │      │ /var/lib/...media   │
                    └───────▲────────┘      └───────▲─────────────┘
                            │                       │
        ┌───────────────────┴────────┐              │
        │ Очередь задач (app/queue)  │              │
        │  N воркеров-потоков        │              │
        └───────┬────────────────────┘              │
                │                                   │
        ┌───────▼─────────────────────────┐         │
        │ Конвейер (app/pipeline.py)      │─────────┘
        └───┬───────┬────────┬────────┬───┘
            │       │        │        │
         KIE API  KIE API  ffmpeg  faster-whisper
        (чат/TTS/видео/картинки)
```

## Этапы конвейера

| Этап | Что делает | Прогресс |
|---|---|---|
| `script` | Чат-модель пишет сценарий и разбивает его на сцены | 10% |
| `voice` | Озвучка каждой сцены, файлы в `media/<канал>/<id>/audio/` | 35% |
| `visuals` | Клипы Seedance и/или фрагменты из библиотеки, `media/<канал>/<id>/clips/` | 65% |
| `assemble` | Каждая сцена — отдельный ролик с озвучкой и вшитыми субтитрами | 80% |
| `metadata` | Заголовок, варианты, описание, теги, фраза для обложки | 90% |
| `thumbnail` | Обложка nano-banana-2 с заголовком поверх (фолбэк — кадр сцены) | 93% |
| `scenes_ready` | Ждём выбора сцен в панели | 95% |
| сборка | Задача `assemble_final`: склейка выбранных сцен, музыка, общие субтитры | 100% |
| `shorts` | Отдельная задача: нарезка вертикальных фрагментов с заголовком | — |

## Устойчивость

- **Идемпотентность.** Этапы пропускаются, если артефакты уже есть **на диске**
  (проверяется существование файла, а не только запись в БД). Кнопка «Продолжить сборку»
  дожимает ролик с места остановки, не переплачивая за готовое.
- **Фолбэки.** Озвучка: второй провайдер. Обложка: кадр из ролика. Субтитры: тайминги по сценам,
  если ASR недоступен. Видеоряд: сцена без клипа берёт ближайший удачный.
- **Предохранитель.** Провайдер озвучки, упавший дважды подряд, выключается на 10 минут —
  остальные сцены сразу идут к рабочему движку.
- **Очередь.** Захват задачи через `UPDATE ... RETURNING` + блокировка в процессе: два воркера
  не возьмут одну задачу. При рестарте зависшие задачи возвращаются в очередь.
- **Ретраи.** HTTP 5xx/429 к KIE — три попытки с нарастающей паузой. Пустой ответ чат-модели
  или 524 от шлюза — до трёх повторов.

## Источники видеоряда

Каждой сцене нужно `ceil(длина озвучки ÷ «секунд на клип»)` кадров, не более шести.
Слоты распределяются между генерацией и библиотекой по режиму канала:

| Режим | Что происходит |
|---|---|
| `generate` | все кадры генерирует Seedance |
| `library` | все кадры режутся из загруженных футажей — бесплатно |
| `mix` | слоты чередуются согласно доле «процент из библиотеки» |

Фрагменты из библиотеки выбираются так, чтобы не пересекаться между собой в пределах ролика:
`SegmentPicker` хранит занятые интервалы по каждому файлу. Футажи ранжируются по совпадению
тегов с заголовком и описанием сцены, при равенстве — по числу прошлых использований,
чтобы библиотека расходовалась равномерно. Если библиотека пуста или фрагмент не удалось
вырезать, слот молча уходит в генерацию.

## Расчёт стоимости ролика

Стоимость определяется в основном видеорядом:

```
клипов = сумма по сценам ceil(длина_озвучки_сцены / «секунд на клип»)
кредиты ≈ клипов × длительность_клипа × тариф_модели_за_секунду
```

Для 7-минутного ролика на `seedance-1.5-pro` 720p без звука (3.5 кредита/с),
клип 5 с и покрытием 20 с: ≈ 24 клипа × 5 с × 3.5 ≈ 420 кредитов ≈ $2.1.
Ползунок «секунд на клип» в настройках канала — главный рычаг цены против разнообразия кадра.

## Локальный ComfyUI

Видеоряд — самая дорогая часть ролика, и его можно считать не в облаке, а на своей
видеокарте. Озвучка, обложки и сценарий при этом остаются на KIE: локально считается
только видео, дальше всё как обычно — ffmpeg сшивает кадры, кладёт голос и субтитры.

Куда подставлять промпт, завод не угадывает: номера нод у всех разные и меняются при
любой правке графа. Вместо этого в графе расставляются метки (`%PROMPT%`, `%SECONDS%`,
`%WIDTH%`, `%HEIGHT%`, `%FRAMES%`, `%SEED%`, `%NEGATIVE%`), и `app/comfy.py:fill`
заменяет их, сохраняя тип: метка, занимающая всё поле целиком, уходит числом, а не
строкой — ComfyUI строг к типам своих входов.

Связать сервер и домашнюю видеокарту можно с двух сторон:

| Способ | Как идёт соединение | Что нужно настроить |
|---|---|---|
| `agent` | изнутри наружу: скрипт на компьютере сам спрашивает работу | ничего, кроме токена |
| `direct` | снаружи внутрь: сервер стучится в ComfyUI по адресу | туннель, проброс порта или VPN |

Режим `agent` — основной: ComfyUI не выставляется в интернет вообще. Очередь живёт в
таблице `comfy_tasks`, агент берёт задание через `GET /api/comfy/next` (метки к этому
моменту уже подставлены сервером — скрипт на компьютере не надо обновлять при правке
правил подстановки) и возвращает клип через `POST /api/comfy/<id>/result`. Ручки агента
живут вне сессии администратора и проверяют свой токен постоянным по времени сравнением.
Задание, зависшее у агента дольше 30 минут, возвращается в очередь: компьютер могли
просто выключить. Файл от агента принимается, только если `ffprobe` читает его как видео
с ненулевой длительностью — обрезок не должен уехать в монтаж.

Сам скрипт — `deploy/comfy_agent.py`, один файл на стандартной библиотеке: панель отдаёт
его по `/comfy/agent.py`, так что на домашнем компьютере нужен только Python.

Ноды в чужой сборке завод не ищет и не подбирает: граф выгружается из того самого
ComfyUI, где потом и считается, поэтому номера нод и связи в нём уже правильные.
Посмотреть, что установлено, можно командой `--inspect` — она печатает список нод и
названия моделей из `/object_info` ровно в том виде, в каком их ждёт граф. Перед каждым
запуском граф сверяется с этим списком (`preflight` — и в агенте, и в `ComfyClient` для
прямого режима): отсутствующая нода останавливает задание с внятной причиной, а
несовпавшее имя модели уходит предупреждением в журнал. ComfyUI отверг бы такой граф и
сам, но его ответ пришлось бы расшифровывать, а в очереди должна быть читаемая строка.
Если `/object_info` недоступен, проверка молча пропускается — она не должна мешать работе.

## Догенерация сорвавшихся роликов

Срыв сборки почти всегда внешний: кончились кредиты KIE, провайдер ответил 500,
оборвалась сеть. Ролик с такой ошибкой не ждёт человека — раз в 10 минут планировщик
зовёт `recovery.run_retries()`, и тот возвращает в очередь те ролики, чью причину
имеет смысл переждать.

Две вещи удерживают это от превращения в дорогую карусель. Повторная сборка не платит
за готовое: конвейер продолжает с места срыва, а сцены, озвучка и кадры остаются на
диске. И пауза между попытками растёт — 10, 20, 40 минут и дальше до потолка в 6 часов,
после двенадцатой попытки ролик остаётся человеку.

Причины делятся на два списка. `TRANSIENT` — то, что проходит само (402, 429, 5xx,
таймауты, обрыв связи, молчание агента). `PERMANENT` — то, что повтор не лечит (граф
просит ноду, которой нет; в запросе не хватает поля; модель не найдена): такие ролики не
трогаем, иначе завод будет бесконечно биться в ту же стену. Проверка идёт в этом
порядке — сообщение про кривой граф и сообщение про кончившиеся кредиты выглядят
одинаково тревожно, но первое не пройдёт никогда.

## Архив готовых материалов

Второй способ наполнять канал: не генерировать, а принести готовое. Архив — это папки по
номерам серий (`001`, `002`…), в каждой обложка и тексты: `metadata.json` с описаниями
для площадок, `cover_copy.json` с крючком, `metadata.md` и `prompt.txt` для человека.
Завод заводит по ролику на папку.

Экономика тут другая. Генерировать нечего — ни сценарий, ни видеоряд, ни обложку, —
поэтому API тратится только на озвучку и фоновую музыку. Для сотни серий это разница в
два порядка против обычной сборки.

Что откуда берётся. Озвучка — из описания для YouTube: оно написано связным текстом и уже
начинается с того же крючка, что на обложке (запасной вариант — подпись для Instagram, но
из неё вычищаются хэштеги: вслух их не читают). Язык берётся из `metadata.json` и
переводом не трогается; вместе с языком подбирается и описание голоса, иначе gemini-tts
читает английский текст с русским акцентом.

Обложка сделана как обложка: крупный текст во весь верх кадра. Поэтому она висит
нетронутой первую секунду — ровно тот миг, на который её рисовали, — а потом за полсекунды
притемняется на `COVER_DIM` и дальше работает фоном под титры. Гашение идёт выражением по
времени внутри того же фильтра, что оживляет кадр, поэтому лишнего прохода ffmpeg нет.
Титры, попадающие на первую секунду, сдвигаются: поверх обложки они превратили бы начало
в кашу, а обрывать озвучку ради этого нельзя.

Серии ищутся по содержимому, а не по глубине вложенности: архив пакуют то с внешней
папкой, то без неё. Пути из архива проверяются перед распаковкой — имя вида `../../etc`
иначе распаковалось бы за пределы своей папки.

Расписание посуточное: `per_day` серий в день, ноль — все разом. Планировщик раз в час
ставит в очередь то, чему пришёл срок; кнопки в панели позволяют запустить серию или весь
архив руками.

## Пакет mens_circle.production.v2

Второй формат архива, и отличается он не составом файлов, а тем, кто принимает решения.
В первом формате завод сам решал, что озвучить (описание для площадки) и что показать
(притемнённая обложка). Здесь всё решено заранее: речь лежит в `script_<язык>.txt` и
озвучивается байт в байт, кадры нарисованы и разложены по сценам в `storyboard.json`,
обложка локализована. Генерация при импорте запрещена целиком.

Формат определяется по корневому `production_import.json` с `packageFormat`, и решение
принимается ДО разбора папок: подсунуть такому пакету логику прежнего архива нельзя —
он озвучит не тот текст. Прежний формат продолжает работать как работал.

Импорт пакета сразу выставляет запреты настройками архива (обложка только из архива,
музыка и рекламная концовка выключены, стиль титров `story`), чтобы человеку не
приходилось помнить про каждый запрет отдельно.

Видеоряд собирается из сюжетных кадров: обложка лежит поверх первого кадра и уходит к
1000 мс — первый кадр к этому моменту уже на месте, поэтому провала в чёрное нет.
Дальше кадры сменяются коротким кроссфейдом. Точных таймингов слов до озвучки не
существует, поэтому время между сценами делится пропорционально числу слов в их beats:
это единственная общая мера между текстом и звуком, и промах в доли секунды не виден.

Повторно использованный кадр — норма, а не ошибка: в реальном пакете у 088 финальная
сцена намеренно берёт `02.png`. ID сцен сохраняются как пришли и не перенумеровываются.

Чего в этой версии ещё нет: рендера Remotion `ArchiveStory`, пословного раскрытия
титров через clip-path, проверки alignment по SHA-256 аудио и валидации SHA256SUMS.
Титры собираются ASS-стилем `story` (Georgia, цвет `#F3F0E9`, без подсветки слова,
страницы до четырёх строк) — это близко к контракту, но не он.
