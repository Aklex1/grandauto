# Кэш страниц на genius-bot.ru

Сборка страницы занимала 1,0–1,4 с чистого времени сервера (до этого, с
сессиями на каждой странице, — 1,8–2,7 с). Готовый файл из кэша отдаётся за
**0,31 с**, и это почти целиком дорога до сервера, а не работа на нём.

Кэширует **WP Super Cache** — он уже стоял в плагинах, но был выключен.
Настройки живут в базе сайта, не в этом репозитории, поэтому записаны
здесь: после переустановки плагина или переноса сайта их придётся
выставить заново, а по памяти они не восстанавливаются.

## Что включено и почему

| Настройка | Значение | Почему так |
|---|---|---|
| Кеширование | включено | — |
| Метод доставки | **Простой** | «Экспертный» режим правит `.htaccess` и отдаёт файлы через Apache. На Beget впереди стоит nginx, и такая связка легко даёт статику в обход PHP — включая ту, которую отдавать нельзя. Разница между режимами — десятки миллисекунд, разница с отсутствием кэша — секунда. |
| Ограничения кеша | не кэшировать для авторизованных | В кабинете на экране баланс. Вошедший всегда получает живую страницу. |
| Не кэшировать адреса с `?` | **выключено** | Сначала было включено, и это ошибка: постраничная навигация каталога живёт на `?gs_page=2..20`. Вместо огульного запрета закрыты конкретные типы страниц. |
| Игнорировать параметры отслеживания | включено | Главная настройка из всех. Яндекс подклеивает к ссылке из выдачи `ysclid`, Google — `srsltid`, соцсети — `utm_*`. Без неё каждый такой адрес для кэша — отдельная страница, то есть **весь поисковый трафик** гарантированно получает страницу, собранную заново. |
| Страницы поиска (`is_search`) | не кэшировать | У запроса бесконечное число вариантов: кэш забился бы мусором. |
| Авто перестройка кэша | включено | Пока файл пересобирается, гость видит предыдущую копию, а не ждёт. |
| Дополнительная сверка кэша | включено | Рекомендация плагина против устаревшей главной. |
| Срок жизни файла | 10800 с | При включённой предзагрузке (ниже) сбор мусора отключён, и это значение почти не работает. Оставлено как страховка. |
| Предзагрузка | все 359 записей, каждые 720 мин, с таксономиями | Без неё кэш помогает второму гостю страницы, а не первому. Трафик у сайта поисковый и длинный: на страницу приходит около одного человека в час, и каждый платил бы полную сборку. 359 страниц дважды в сутки — около семи минут работы PHP за день. |
| Сжатие кэша | выключено | Плагин сам предупреждает, что на части хостингов ломается; nginx на Beget жмёт ответы сам. |

## Что нельзя кэшировать

Защита в два слоя. Первый — список адресов в самом плагине кэша, он
работает **до** загрузки WordPress. Второй — константа `DONOTCACHEPAGE`,
которую объявляет `GS_Cache` (`includes/class-gs-cache.php`) на
`template_redirect`; она не даёт создать файл, даже если адрес в список не
попал.

Второй слой нужен именно потому, что первый — список, который однажды
забудут дополнить. `GS_Cache::paths()` собирает адреса из тех же реестров,
по которым страницы и создаются (`GS_Lab::services()`, `GS_Api_Page::SLUG`,
`GS_Pages::STUDIO_SLUG`, `GS_Slides_Page::SLUG`), поэтому **новый
микросервис закрывается сам**. Руками там перечислены только кабинеты чужих
плагинов: `neurohub`, `pdf-online`, `showwheel`.

Список в плагине кэша (Настройки → WP Super Cache → Настройки →
«Настройки отклонения URL»):

```
wp-.*\.php
index\.php
^/wp-json/
^/api/
^/tts-login
^/tts-dashboard
^/sound-generator
^/sozdat-prezentaciyu
^/sozdat-muzyku
^/pesnya-svoim-golosom
^/govoryashchiy-avatar
^/rasshifrovka-audio
^/zvuk-iz-video
^/ubrat-vokal
^/ubrat-shum
^/neurohub
^/pdf-online
^/showwheel
```

Строки применяются как регулярные выражения к `REQUEST_URI`. Якоря `^/`
здесь не украшение: без них правило `/api/` поймало бы и статью
`/api-nejroseti-besplatno/`.

Отклоняемые cookie: `PHPSESSID`. У кого есть сессия PHP — тот получает
живую страницу. Сессии остались только на страницах выше (см.
`wp-plugins/patches/README.md`), но кука — признак надёжнее списка адресов.

## Как проверить, что всё на месте

Кэш отдаётся (в ответе есть слепок, время сервера — треть секунды):

```bash
curl -s -o /tmp/p.html -w '%{time_appconnect} %{time_starttransfer}\n' \
  https://genius-bot.ru/izvlech-zvuk-iz-video-onlayn/
grep -o 'Cached page generated by WP-Super-Cache on .*' /tmp/p.html
```

Ссылка из Яндекса не создаёт второй копии — слепок тот же, что у чистого
адреса:

```bash
curl -s https://genius-bot.ru/izvlech-zvuk-iz-video-onlayn/?ysclid=test \
  | grep -o 'Cached page generated by WP-Super-Cache on .*'
```

Личная страница в кэш не попала (в ответе слепка быть не должно):

```bash
for p in tts-dashboard api neurohub pdf-online showwheel zvuk-iz-video; do
  echo -n "$p: "
  curl -s "https://genius-bot.ru/$p/" | grep -c 'WP-Super-Cache on'
done
```

Что лежит в кэше целиком — Настройки → WP Super Cache → вкладка
«Содержимое», ссылка «Обновить статистику кэша». В списке должны быть
только публичные адреса.

## Чего кэш не лечит

Страница весит 154 КБ разметки на 2,5 КБ текста, и это остаётся при любом
кэше: он ускоряет ответ сервера, а не загрузку в браузере. Облегчение
шаблона — отдельная задача.
